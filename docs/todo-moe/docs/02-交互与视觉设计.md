# 交互与视觉设计

**设计目标：任务正文清楚，记录与完成顺手；玻璃集中在浮动操作区域，动画提供反馈。** 本文件是设计规范草案，数值是初始调参值，未经过目标设备验证。

## 1. 信息结构与常用路径

| 页面/区域 | 主要内容 | 核心动作与异常 |
|---|---|---|
| 今天 | 当日相关任务与空状态 | 完成、撤销、查看所属清单；筛选变化不触发清单庆祝 |
| 清单 | 文件夹 → 清单 → 分组 | 展开/折叠、进入、移动；数量按真实数据计算 |
| 收件箱 | 尚待整理的任务 | 快速记录、后续归类；隐藏高级入口不删除上游能力 |
| 独立 ＋ | 快速添加面板 | 输入、提交、关闭；保存失败保留输入和可重试状态 |
| 设置/关于 | 主题、动效、触感、同步入口、版本与来源 | Dev 标识清楚，真实同步凭据不出现在诊断导出 |

建议让新增从常用页面均可达，按钮使用一致含义。将“新增”与页面切换区分；返回关闭当前面板/键盘后仍回到合理页面。搜索与任务详情沿用上游能力，按新的导航验证入口。

## 2. 文件夹与清单

| 可见名称 | 候选上游实体 | 设计要求 |
|---|---|---|
| 文件夹 | Area | 清楚呈现所属清单和展开状态 |
| 清单 | Project | 显示名称、必要的数量/进度，允许进入分组 |
| 分组 | Section | 同一清单内部组织，不复制任务 |
| 任务 | Task | 复用原业务操作和稳定 ID |
| 标签/高级 GTD | 上游既有实体 | 通过高级视图访问，具体位置按基线页面核对 |

空清单显示添加入口；长名称、中文换行、大字体、深层滚动均需可读。折叠动画不能把焦点留在不可见子项，也不能导致数量与数据脱节。

## 3. 主题与玻璃

| 区域 | 默认视觉 | 验收重点 |
|---|---|---|
| 底部导航 | 主要玻璃区域，可选液态/柔和/关闭 | 背后 RN 列表变化实时反映；图标、文字和选中态清楚 |
| 快速添加 | 轻磨砂、清楚输入区 | 键盘弹出后仍可看到输入和提交按钮 |
| 搜索/浮动工具条 | 少量模糊与高光 | 不压低正文对比度，不抢主要操作注意力 |
| 任务正文 | 浅色或深色实底为主 | 不因背景变化影响阅读，完成态仍能辨认 |
| 文件夹/清单卡片 | 图标、留白与主题色区分 | 颜色之外还有文字和形状提示 |

三套预设建议：柔白玻璃、墨色玻璃、家族强调色。家族 Logo 的主体、比例与线条来自用户实际素材，再添加小清单或勾选识别元素；当前没有素材，不能标记图标已完成。Material You 动态色为增强候选，需提供固定颜色回退。

设置建议如下，实际文案可在实现时微调：

| 设置 | 候选值 | 行为 |
|---|---|---|
| 玻璃效果 | 关闭 / 柔和 / 液态 | 不可用时降级；关闭后保留导航、选中态和全部操作 |
| 动画强度 | 简洁 / 标准 / 活泼 | 改变表现，不改变保存时机或功能可用性 |
| 触感反馈 | 关闭 / 轻 | 无硬件或关闭时静默跳过，不影响业务 |
| 主题 | 柔白 / 墨色 / 家族色 | 配合系统外观时仍保持正文和图标对比度 |

## 4. 完成操作的状态与动效

用户点击完成时，立即通过上游业务接口发起状态变化；UI 同时反馈。视觉退出可延后，业务调用不得等待动画结束。若上游本身异步保存，应保留其原本的一致性与错误处理语义，不能在 UI 里另造“已经永久保存”的假象。

```text
点击完成
  ├─ 原有完成操作：更新/持久化/重复任务处理（使用原接口）
  │    ├─ 成功 → 维持业务状态
  │    └─ 失败 → 按原语义恢复一致状态，提示重试
  └─ 视觉反馈：勾选、划线、触感、行退出
       └─ 只保留临时视觉节点；不得再保存一份任务
```

| 阶段 | 初始参数建议 | 约束 |
|---|---|---|
| 勾选 | 缩放 1 → 0.88 → 1.16 → 1，约 250 ms | 快速连点不能重复写入或重复创建下一次任务 |
| 划线 | 画出勾与短划线，正文透明度候选到 0.48 | 大字体与深色下仍能辨识，参数可因对比度调整 |
| 轻触感 | 完成时一次轻反馈 | 同步回放不反复震动；关闭触感不影响操作 |
| 行退出 | 水平位移候选 12，淡出并平滑收起，约 250–350 ms | 适用需移出当前视图的行；已完成视图不无条件消失 |
| 失败/撤销 | 取消过时动画，以最新业务状态重建表现 | 不让退出节点盖住恢复任务，不用动画结束回调触发新写入 |

多个任务可同时完成，不要求等待动画队列。列表虚拟化、切页、应用后台/重启后，任务状态以数据源为准；卸载组件必须清理视觉占位与回调。

## 5. 清单完成庆祝

建议仅在本机用户的成功完成动作让一个明确的清单从“有待完成项”变为“已完成”时播放一次小范围庆祝。实施前先在业务层核对该清单“完成”的既有定义，包括归档、删除、重复、子任务和筛选语义。

| 情况 | 预期 |
|---|---|
| 用户成功完成清单最后一个有效待办 | 可播放一次，按稳定事件或操作 ID 去重 |
| 切换筛选、空清单初次打开、仅当前页面变空 | 不庆祝 |
| 其他设备同步完成、重复渲染/重新进入页面 | 默认不庆祝 |
| 保存失败、撤销、重复任务立即生成下一项 | 按真实业务状态判断；不能以旧可见列表误报清单完成 |
| 减少动画、关闭庆祝或当前不可见 | 简化为清楚的完成提示，保留相同行为结果 |

“今天全部完成”是另一个可选庆祝范围，不能复用“清单完成”的标题或计算；只有在 v0.3.0 明确定义日期边界、时区和范围后再启用。

## 6. 其他交互动画

| 动作 | 起始设计 | 必须通过的行为 |
|---|---|---|
| 文件夹展开 | 箭头旋转，内容高度/透明度变化，约 100–250 ms | 连续开关不闪回，滚动位置与焦点合理 |
| 新增任务 | opacity 0 → 1，translateY -8 → 0，scale 0.98 → 1，约 180–220 ms | 一次提交一条任务，失败保留输入，排序/筛选决定实际位置 |
| 按压反馈 | scale 1 → 0.975 → 1，弹性回弹 | Task/Project/Tag/Button/FAB/Card 复用配置，拖动时不误触 |
| 滑动动作 | 位移跟手、图标随阈值变化、跨阈值轻触感 | 取消手势不执行，完成/删除遵守上游确认及撤销规则 |
| 页面转场/清单卡片 | 轻量过渡与稳定布局 | 优先级低于可用性；系统减少动画时简化 |

统一参数候选：fast=140 ms、normal=220 ms、slow=320 ms；spring damping=16、stiffness=220、mass=0.75。上述值源于聊天建议，需集中定义后真机调参，不能称为已调优结果。

## 7. 玻璃技术验证与降级

优先复用用户其他项目中成功使用的 SukiSU 底栏版本。完整来源链包含原文件、辅助文件、背景采样位置、依赖和来源提交；只复制 FloatingBottomBar.kt 不算接入完成。

RN 可滚动测试列表与原生底栏构成最小样例。滚动多色文字/图形内容，检查底栏后方是否实时变化，同时录屏并采集性能。不能仅看半透明截图判断“动态折射通过”，也不采用 JS 定时截图代替实时采样。

验证点击、拖动选择、系统返回、RN 页面手势、键盘、手势安全区、旋转、前后台恢复。关闭玻璃和减少动画分别比较。Android 系统/渲染能力不满足时，使用清楚的不透明或轻量背景；失败记录中写明哪条路线不可用、为什么、采用什么回退。

## 8. 无障碍与日用边界

| 维度 | 要求 |
|---|---|
| 读屏 | 导航、完成按钮与展开状态有清楚名称/状态，装饰粒子不抢焦点 |
| 字体与触控 | 系统大字体下按钮和标题可用；候选触控目标至少 48 dp，最终由真机验证 |
| 减少动画 | 使用明确设置，若框架支持则尊重系统设置；禁用位移/粒子后结果同样清楚 |
| 可读性 | 浅色、深色、家族色和玻璃关闭均检查对比，不只依赖颜色表示完成 |
| 负载 | 大清单、快速连点、重复进入页面不累积计时器/视觉占位，性能以关闭玻璃对照 |
