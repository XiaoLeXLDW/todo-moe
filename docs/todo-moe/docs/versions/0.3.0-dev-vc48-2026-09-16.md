## 根因与修复

1. 完成提示原来会被新完成提示直接替换，插入错误提示时可能形成 `A → B → E`。现在已被用户看到且可撤销的完成提示保持当前，错误提示紧随其后，更新后的完成提示排在错误后，锁定为 `A → E → B`；撤销测试使用真实延迟 Promise，确认提示等待业务结算。
2. 项目文件夹/标签更新完成后，旧项目 A 的异步回调可能在用户已打开项目 B 时继续发布 A 的界面状态。共享更新入口现在在业务写入成功后再次检查选择会话：写入仍完成，但过期 UI 不再覆盖当前项目。
3. Android 和 iOS 的文件夹、标签选择器统一使用 `projectId + visible + revision` 会话保护；同一项目关闭再打开也会递增 revision，旧回调不能写入新一轮面板。
4. UTC 周期测试原来依赖运行日期，2026-09-16 跨过默认 7 天自动归档边界后远端失败。测试夹具显式关闭自动归档，固定它真正要验证的重复项目再激活语义。
5. 共享滑动动作轨移入 Todo Moe 展示目录，项目卡片与任务行继续复用同一单向左滑样式；本轮没有改动任务/项目数据 schema、同步协议或触感。

审查包提出的项目详情原生 Modal 可能采样到首页而非详情页属于风险项。真机打开“快速上手”详情再打开文件夹选择器时，玻璃面板后方可见详情标题、说明和任务行，面板位于最上层且未被遮挡；本轮未为未复现风险改写原生玻璃实现。
