## 目标与范围

交付一个经过用户日常操作、数据恢复、签名升级与发布闭环验证的 Android 日用稳定候选。把“构建得出”“手机可安装”“日用可靠”分开判定。

| 纳入范围 | 本版不做 |
|---|---|
| 以确定源码、确定 APK、确定默认效果进行完整日用验收 | 不边日用边大改导航、同步协议或底层数据库 |
| 快速记录、多清单、全套交互、玻璃降级和无障碍回归 | 不把所有历史助手建议都扩成 1.0 必做功能 |
| 备份/恢复、离线与云同步、Dev/Stable 隔离、正式升级 | 不在备份恢复未验证前把真实任务当测试样本 |
| 从预发布/正式候选到稳定发行的追溯和说明 | 不把已上传 APK、单次截图或静态检查算作日用通过 |
| 缺陷收敛、日用问题记录与维护交接 | 不承诺未测试设备/系统/全部同步服务兼容 |

1.0 的“稳定”范围写明实际设备、系统、同步后端和启用功能。优先用实际日用的一个同步后端形成可靠闭环；未测后端保留原能力且列为未验证，不声称全面适配。

## 日用验收安排（建议）

先完成隔离测试与可恢复备份演练，再决定真实待办的迁入方式。建议以同一稳定候选连续试用至少 7 个自然日，覆盖离线记录、跨设备同步、重复任务跨日、前后台切换、键盘输入和批量完成。7 日为本次建议的观察窗口，不是用户已承诺排期，也不是“不出错 7 日即永不丢数据”的保证。

每日记录候选版本/哈希、实际用过的流程、错误或视觉问题及能复现的步骤。没有运行的项目写“未覆盖”。若中途更换候选，保留版本对应的观察记录；涉及数据、同步、完成逻辑或发布身份的修复，应重新执行相关验收，并明确是否重新开始观察窗口。

玻璃默认档与动画强度以日用设备表现决定：完整功能与可读性优先，合格的柔和玻璃或实底可作为正式默认。若原计划液态效果未达到要求，应在发行说明明确实际效果和限制，不能换名宣称同等实现。

## 验收用例与通过条件

以下 `V10-*` 是 [统一 QA 矩阵](../05-测试与发布维护.md#2-测试矩阵) 的稳定验收细项：V10-01→QA-03/08；V10-02/03→QA-06/07；V10-04/05→QA-10；V10-06→QA-02；V10-07→QA-04/05/14；V10-08→QA-09；V10-09→QA-13；V10-10→QA-14；V10-11→QA-11。QA-01/12 的前版证据也须对应本次继承基线；变更相关构建/同步流程时重跑。

| 用例 | 验证内容 | 通过条件 |
|---|---|---|
| V10-01 记录和整理 | 首页快速添加、连续输入、文件夹/多清单/分组、编辑/移动/排序（实际支持范围） | 路径直观，内容去向清楚，数据重启后正确；高级数据仍可找到 |
| V10-02 完成反馈 | 完成、添加、按压、滑动、展开/收起、真实清单庆祝 | 动画一致且不拖慢连续操作；真实清单/筛选/同步/重复/撤销边界符合 v0.3.0 |
| V10-03 失败与恢复 | 可控保存失败、操作中断、撤销、重复点击、触感失败 | 无成功假象、无数据丢失或重复后继，能恢复继续用 |
| V10-04 同步与离线 | Dev/Stable 不同云端目录，离线编辑、双端改动、失败重试、恢复联网 | 测试数据未跨入日用空间，选定后端兼容，结果与上游语义一致；失败明确 |
| V10-05 备份恢复 | 导出含清单/分组/完成/重复等测试数据，在隔离环境恢复并逐项比对 | 备份可读取可恢复，关键字段和状态一致；唯一备份未被覆盖；真实迁入方案可执行 |
| V10-06 正式身份升级 | 正式签名候选从先前同身份构建连续升级，核对 versionCode/签名/配置/数据 | 不卸载、不清数据即成功；来源/关于页/安装包元信息一致；Dev 不能被误覆盖 |
| V10-07 玻璃与布局 | 默认效果下滚动、键盘、安全区、系统返回、横竖屏、前后台 | 动态能力与 v0.2.0 结论相符，不卡顿到影响输入，降级完整且可保存 |
| V10-08 无障碍与主题 | 减弱动画、关闭触感/玻璃、朗读、大字号、明暗/家族主题 | 任务与操作状态可辨、焦点与触达正确，简洁模式没有粒子/大幅位移依赖 |
| V10-09 发行闭环 | 固定批准 commit→正式 APK→下载哈希→手机渠道识别/覆盖更新 | 各环节可追溯，Stable/Dev 匹配正确，正式秘密和真实数据未出现在日志 |
| V10-10 日用观察 | 在记录的设备和同步后端执行约定观察窗口 | 记录完整，阻断使用、丢数据、错同步、升级失败类问题为零；剩余轻微问题列明并接受 |
| V10-11 原有系统能力 | 检查实际保留的提醒、Widget、通知、权限和后台行为 | 品牌/导航/升级未破坏选定基线已支持能力；受系统限制项如实说明 |

“问题为零”指观察和测试中没有未解决的此类问题，不是证明绝无潜在缺陷。未跑的环境和用例保持未验证。

## 放行标准与失败分支

| 情况 | 处理 |
|---|---|
| 存在数据丢失、重复生成、串用云端目录、正式升级失败或频繁崩溃 | 不发布 1.0；保留候选与证据，定位修复，完成受影响的回归 |
| 玻璃或动画存在性能/可访问性问题 | 选择已验收的降级默认，或回退问题效果；版本说明记录差异，重测默认配置 |
| 核心用例缺设备/后端/观察记录 | 状态保持候选、未验证；不能用自动化全绿替代缺失验收 |
| 只有轻微视觉问题且不影响核心路径 | 给出复现、影响、暂行办法和是否接受；保留为后续补丁，不掩盖在“全部通过”中 |
| 1.0 发行后发现问题 | 记录受影响版本，准备更高 versionCode 的修复版；根据数据兼容情况决定恢复步骤，不假定旧 APK 可直接降级 |

最终放行记录需写明用户体验验收结论、执行者与日期、候选 commit/APK 哈希和接受的限制。没有正式发行授权或外部环境时，交付完整可审阅候选与文档，发布状态保持未发布。
