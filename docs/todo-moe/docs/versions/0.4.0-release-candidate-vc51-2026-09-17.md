# 0.4.0 Stable vc51：PR #14 正式发布候选

本版把 Todo Moe 的 checklist / `taskMode=list` 从“只能进编辑器维护”提升为任务列表中的直接执行界面。正式 APK 必须由 PR #14 合并到 `main` 后的批准源码经受控工作流重新检查、构建和正式签名，不能把 Dev APK 政名发布。

## 收录范围

1. list 任务折叠时显示完成进度；点任务主体展开或收起，逐项圆形按钮直接持久化 `checklist[].isCompleted`。
2. 完成项保持原顺序，只做淡化和删除线；小步骤使用低于父任务一级的弹性、划线、粒子与触感反馈，取消完成有反向反馈。
3. 最后一个未完成步骤写入时同时完成父任务；撤销精确恢复父任务和最后一步，不覆盖此前完成的其他步骤或后来发生的 checklist 编辑。
4. 排队写入按稳定 `itemId` 对实时 checklist 重放，保留并发改名、新增、删除和排序；只读、归档、多选及过期回调继续受保护。
5. 编辑器保存失败保留草稿，旧异步会话不能关闭后来打开的任务；管理文件夹和引用分组弹层修正拥挤并统一玻璃层级。

没有新增子任务 schema，没有把 checklist 转成 Project Task，也没有重做底栏、AI、同步、图标或发布系统。

## 正式发布门禁

- 语义版本：`0.4.0`；Stable versionCode：`51`；预期 tag：`moe-v0.4.0-vc51`。
- PR #14 合并后，只接受可从 `origin/main` 到达的完整批准 SHA。
- 受控工作流必须重新通过检查、无签名构建、正式密钥隔离签名、证书指纹和 APK 哈希回读。
- GitHub Release 必须包含签名 APK、`SHA256SUMS`、`release-manifest.json` 和 `RELEASE-NOTES.md`，并在公开后重新下载核对。

此记录不提前填写正式 APK 大小、SHA-256、证书或 Release URL；这些字段只能从成功的正式工作流和已发布资产回读。
