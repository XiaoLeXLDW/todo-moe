# 需求与范围

**目标：基于 Mindwtr 做个人日用待办，主要改善 Android 上的清单体验、动画、品牌与玻璃效果。**

来源为 [聊天原文](sources/chatgpt-推荐待办应用-2026-09-11.md) 第 1–3 轮，以及本次明确要求“按现有聊天整理开发方案和分版本文档”。本文件保留需求定义，以下“应实现”“应验证”是验收要求；当前实现与证据见 [执行台账](../IMPLEMENTATION.md)，不再将规划时状态当作当前进度。

## 3. 产品默认结构

用户面对“文件夹 → 清单 → 分组 → 任务”；建议分别复用上游 Area、Project、Section 和 Task。此处是界面词汇映射，不新增一套同步层级。源码字段、存储位置与约束在选定上游提交后核对。

首版默认导航为“今天 / 清单 / 收件箱”，新增使用独立“＋”，设置在右上角。其他 GTD 功能保留在高级入口，不先删除数据能力。最终导航依据真机快速记录流程调整，不能只凭静态效果决定。

主题建议为“柔白玻璃 / 墨色玻璃 / 家族强调色”。设置只暴露玻璃效果、动画强度和触感反馈等可理解的选项；详细参数留在代码配置。

## 5. 第一轮保留与暂不做

| 类型 | 内容 | 原因或处理 |
|---|---|---|
| 保留 | 上游任务模型、完成/重复任务逻辑、持久化、同步能力 | 降低数据与上游合并风险，允许小范围有证据的必要接入 |
| 保留并回归 | 提醒、标签、搜索、现有 Widget 和高级 GTD 能力 | 改名和重排导航可能影响入口；实际支持范围以选定基线为准 |
| 优先改 | 品牌、移动端 UI、文件夹清单、动画、主题和玻璃模块 | 对应用户明确需求 |
| 暂不做 | 整个 App 改写 Kotlin、自建同步协议、自建云服务、内置更新器 | 超出首轮体验目标；需要独立立项 |
| 暂不做 | 积分商城、打卡惩罚、养成系统、AI 聊天及每项完成都撒彩带 | 历史助手建议避免的产品扩张，本次采为默认非目标 |

Material You 动态色、HyperOS 圆角风格、页面转场、清单卡片改造作为 v0.3.0 的可裁剪增强项；不优先于可靠操作、可读性与减弱动画。

## 6. 选型讨论如何保留

原聊天先比较 Mindwtr、Memorigi、Tasks.org、Taskito、TaskMate 等应用，之后用户明确询问基于 Mindwtr 二开。竞品名称和当时版本/价格/功能说法仅保存在原文，作为选择背景；本项目不据此维护推荐清单或宣称它们当前仍然如此。

玻璃路线按 v0.2.0 的真实验证结果决定：优先核对用户在其他 App 已使用成功的 SukiSU 版本，其次核对官方当前源码。该“已有成功版本”的路径和提交尚未提供；另一 App 中可用不等于 Mindwtr 中可用。
