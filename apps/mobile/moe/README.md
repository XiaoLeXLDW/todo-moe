# TodoMoe 移动端体验适配层

本目录把 TodoMoe 的本机外观与交互接到 Mindwtr 现有页面、任务和同步接口。任务依然使用原来的 Area / Project / Section / Task、`updateTask`、捕获事务及 `undoTaskCompletion`；这里不新增任务表、不复制持久化任务、不替换同步算法。

## 日常入口

- 底栏固定为「今天 / 清单 / 收件箱」。新增为独立 56 dp 按钮，普通点击遵循原默认捕获方式，长按使用另一种捕获方式。键盘出现时隐藏底栏。
- 右上角是搜索与 TodoMoe 设置；左上角保留文件夹/Area 切换和高级 GTD 菜单。Review、Calendar、Contexts、归档、回收站、已完成、参考资料、已存搜索仍走原有路由。
- 清单页面复用上游项目的分组、数量、筛选、移动和折叠状态。完成按钮新增明确的 checkbox 语义；已完成项的按钮是恢复到收件箱，完成提示中的「撤销」继续调用上游重复任务感知的撤销接口。
- `MoeTabInsetContext` 只在底部导航范围提供 `96 + safeArea.bottom` 的列表空间；独立设置等页面不添加这段空白。项目详情已经明确传入的键盘避让值优先。

## 本机设置

`preferences.ts` 使用 `@todo-moe/presentation/v1` 存储主题、系统明暗、玻璃档位、动画强度、触感及庆祝设置。这些字段不进入同步数据。先读取已有设置再应用编辑；串行写入防止较旧的写入覆盖新选项；失败回滚并在设置页提示。

柔白、墨色、家族色均提供明确的文字与选中态颜色。主题明确选择会关闭「跟随系统明暗」，用户可重新开启。Material You 暂时显示固定颜色回退。液态效果是实验能力，系统版本只表示路线可用，不能代替设备验证。

`haptics.ts` 是所有移动端触感调用的入口。关闭时不调用硬件；开启时用轻触感，硬件错误静默跳过。系统减少动画与「简洁」任一个开启均取消位移/缩放和装饰庆祝。`use-reduced-motion` 为所有行共享一个原生监听，最后一个消费者卸载后释放。

## 完成动作与庆祝边界

1. 按稳定 taskId 取得本机会话操作锁；直接发起原业务操作，不等待动画。
2. Native LayoutAnimation 只持有有限时长的视觉节点，新增/完成/折叠淡变与布局过渡不保存任务副本。原生动效失败也必须继续提交。勾选和划线由任务状态/当前操作的临时反馈驱动。
3. 明确失败恢复按钮并使用原有错误提示；成功沿用完成消息和撤销。撤销会撤掉过时的清单完成提示。
4. 清单庆祝在整个原始任务集合上判断有效待办（inbox / next / waiting / someday，排除删除/参考/归档）。同一清单的并发本机完成操作合并为一个临时批次，所有消失的待办必须能对应到成功本机操作，再检查完成后的完整数据。
5. 筛选变空、空清单初次出现、其他设备同步完成、移动/删除/归档、写入失败和自动创建的重复后继都不会误报清单完成。后台或不可见时不播放；简洁/关闭庆祝时显示同义的静态完成提示。

## 验证与边界

自动测试覆盖三导航与新增独立性、捕获防连点/失败/选定Area/returnTo、100个组件共享一个减少动画监听、色彩对比度、设置持久化与失败、完成即时提交/重试/撤销、并发完成与同步/重复后继等事件边界。

完整的玻璃动态背景、键盘/横屏/返回、读屏焦点、大字体、行退出/折叠的实机连贯性、功耗和帧率仍需要设备证据。这里不把 TS/单测通过称为真机体验通过。`motion.ts` 中数值是文档的初始候选，尚未宣称完成目标设备调优。
